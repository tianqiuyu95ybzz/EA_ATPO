# Reliability-conditioned router: synthetic feasibility pilot

This pilot asks whether a router benefits from knowing that patient-response
availability and expert quality vary by case. It is a hand-coded synthetic
decision-policy simulation, not a medical benchmark, an LLM evaluation, or
evidence of clinical benefit.

## Reproduce

From the workspace root:

```bash
python3 EA_ATPO/experiments/reliability_conditioned_router_20261102/run_experiment.py
```

The run uses only Python's standard library and overwrites `results.json` in
this directory. It evaluates 30 training seeds. Each seed collects 20 binary
outcome rollouts per action and context cell, then evaluates 5,000 test states.
The training mix is balanced. The test mix shifts toward difficult cases, low
patient answerability, and low expert reliability. Every compared router gets
the same 0.20 expert-work units per test case. CONSULT costs one unit and DEFER
costs two; ASK has a separate patient-burden cost.

## Ablations

- `no_reliability`: action values pooled across all contexts.
- `difficulty_only`: action values conditioned on difficulty.
- `patient_reliability`: difficulty plus patient answerability.
- `expert_reliability`: difficulty plus expert reliability.
- `both_reliabilities`: difficulty plus both reliability signals.
- `oracle`: true synthetic action values, as an upper reference.
- `always_answer`: no-intervention reference.

All routers choose between ANSWER/ASK and use the shared expert budget to
upgrade cases to CONSULT/DEFER in descending predicted utility gain per expert
unit. The result evaluates a grouped action-value lookup, not the current frozen
Qwen representation router.

## Synthetic environment

Context is `(difficulty, patient_answerability, expert_reliability)`. The
probability of a correct diagnosis is generated by explicit equations in
`run_experiment.py`. The reliability bins are exposed to the router as perfect
pre-action signals. That assumption is deliberately optimistic; the real
project must estimate signals from public dialogue only and check calibration.

The expected test accuracy is computed from the simulator's known conditional
outcome probabilities, not sampled test labels. Confidence intervals are
paired across training seeds. This is only a feasibility result for the routing
logic and its ablations.
