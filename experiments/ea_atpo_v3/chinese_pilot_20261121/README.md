# Chinese retrospective replay pilot

ReMeDi source and all patient conversations and outputs remain under ignored private directories. The `prepare.py` selection is fixed by source ID and not by outcome; `audit_cases.py` checks chronology and identity. `run_cpu_retry.py` loads the existing pinned Qwen3-8B and writes per-case outputs privately with exclusive creation. It runs original history and historical-question/patient-reply history on the same cases. Historical doctor responses after that feedback are NOT comparable initial-state reference answers. No verified diagnosis Gold, human ratings or safety labels are assumed. The first three-case `run_cpu.py` attempt hit the 96-token cap and is kept separately. The retry limits the requested answer length and records EOS.

The simple router is a retrospective engineering proxy. It selects replay ASK only when the current last patient utterance includes an explicit uncertainty marker and replay availability is known; otherwise it answers. This marker is not proof of a clinically important missing fact; replay availability relies on future records and does not represent prospective access. No dependable high-risk signal was established, so DEFER is not synthesized. Any resulting comparisons require real independent review and cannot establish deployable EA-ATPO effectiveness.
