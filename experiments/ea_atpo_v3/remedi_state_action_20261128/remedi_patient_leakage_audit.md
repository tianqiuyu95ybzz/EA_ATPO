# ReMeDi 划分、近重复与时序审计

固定官方 train/dev/test。已映射的 641/99/777 段对话共 1,517 个唯一对话 ID，跨划分交集为零。40 个有歧义的官方对话块沿用上一轮排除规则。同一对话衍生的每个行为状态、回放窗口及特征输入均继承它的官方划分。原始对话记录仅有对话 ID，未发现患者级 ID，因此同一患者是否跨划分无法验证。本轮未推断患者身份。

完整对话按 Unicode NFKC、大小写折叠和去空白标点规范化，计算字符 5-gram 集合 Jaccard。按全局频率排序进行前缀及长度过滤，候选使用精确 Jaccard 复核。以 0.80 为阈值，已映射对话之间未发现跨划分命中，历史 Pilot 与其他对话没有命中。同一对话 ID 的 Pilot 副本按历史排除规则处理。此方法对长文本局部重合、语义改写及跨记录患者关联的覆盖有限。

历史 50 例输入沿用已按档案哈希逐字节恢复的固定清单。49 例有唯一映射，另 1 例未通过映射。原始 3,506 个回放索引窗口全部复核，历史 50 例在合格队列及特征输入中的命中为零。描述性 `all_prepared` 列仍可看到历史标签计数，`eligible` 列用于排除历史 Pilot 后的候选统计。没有用 Test 标签调参。

Base 特征文件逐条核对为决策前可见对话，字段仅包含关联键、split 和 `public_state`。动作、后续反馈、Gold、Oracle、Q 值均留在其他文件或未提供。已有历史医生 `Diagnosis` 动作之后的决策也从特征输入排除，共导出 10,212 条输入。本轮未提取 embedding，也未做推理或训练。

复现构建前重验六项输入 SHA-256，输出私有 12 个 JSONL 均通过 SHA-256 校验，两次构建的私有数据逐字节一致。近重复方法和阈值记录于汇总。原文、病例 ID、近重复候选及逐条映射只允许在受控环境处理。
