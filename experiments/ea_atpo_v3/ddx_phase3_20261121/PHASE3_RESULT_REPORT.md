# DDXPlus 真实 Base 与 Oracle 配对冒烟（非完整验证）

## 数据与设定

50 条为官方 validation 前 50 行，非随机样本，不是独立测试。前 50 行中无精确重复，也无与官方 train 的完整行精确重复，但缺乏患者 ID，不能排除近重复、预训练暴露或同一潜在病例；全量 train/validation 实际存在 1,625 种完整行相同记录（验证 1,643 行），见 `OVERLAP_AUDIT.json`。没有读取官方 test。详见 `ENGINEERING_AND_ADMISSION.md`。

真实 Base 是固定 Qwen3-8B，CPU、贪心输出、24 token 上限、关闭 thinking；只输入首个证据、官方全部候选病种。Gold 和其他病例证据没有进入 prompt。输出必须与官方病种名称大小写不敏感地完全一致；无法解析计入错误，而不猜测。Base 初始 49/50 正确解析、1/50 未解析；没有可用可靠置信度。ASK 使用固定的、按 ID 排序的第一个未公开独立根证据，返回该合成病例的官方目标状态，再让同一个 Base 重新回答。没有按 Gold 或隐藏事实选问题。数据仅支持合成病种分类，不是临床效果。

## 结果

| 对同一批初始 Base 输出的策略 | Accuracy | 说明 |
|---|---:|---|
| Always ANSWER | 9/50 = 18% | 1 个未解析计错 |
| Always DEFER + Oracle A | 50/50 = 100% | 按定义返回标签，未扣成本 |
| Always DEFER + Oracle B | 50/50 = 100% | 用事后标签判断，仅为上界 |
| Always ASK 一次，再 ANSWER | 2/50 = 4% | 固定问题规则，2 个未解析计错 |

相对 Base，Oracle A 和 B 的无成本 accuracy 均增加 82 个百分点；两者均保留 9 个 Base 正确输出，纠正 41 个错误/未解析输出，破坏正确输出各 0。此封闭分类与完全准确的理想 Gold 下，Base 已正确时其标准标签本来就等于 Gold，故 A/B 均不会破坏；此结果无法体现保护门优于 Standard，也不证明真实 Router 会识别错误或实际医疗文本不会退化。

固定 ASK 纠正 0 例、使 7 个原本正确的输出变错，另有 2 个未解析；Accuracy 差为 -14 个百分点，按行定位符配对 bootstrap 10,000 次的探索性 95% CI 为 [-24,-6] 个百分点。非随机样本和未知病例独立性使区间不能代表总体；这是一个固定 ASK 规则的结果，不能外推到所有提问。模拟器反馈为合成患者状态，不是现实患者的反馈。

成本只扣一次，Utility=Accuracy-ASK 成本-DEFER 成本：Always ANSWER 为 0.18；一次 ASK 在 0.01/0.05/0.10 下分别为 0.03/-0.01/-0.06；全 DEFER 的 A/B 在 0.05/0.10/0.20/0.60 下分别为 0.95/0.90/0.80/0.40。Oracle 使用事后真值且为完美标签上界，不能用于估计可部署系统。没有 DDX 适配的 Q-guided Router、可信置信度或逐动作训练集，故无法给出 Router Utility、误差可识别性或训练效果。按当前结果**不建议启动正式 Router 训练**。

仅完成 50 例冒烟，没有完成完整 validation 的 Base 预测；在已有重复和患者标识不足的问题未澄清、且 GPU 不满足项目资源门槛时，不能宣称完成病例独立的正式验证。下一步需处理跨 split 重复及无 ID 限制、校准诊断解析、验证模拟器证据依赖和动作问句映射，并在独占 GPU 可用时按冻结协议评估。CPU 摘要 `SMOKE_SUMMARY.json` 是唯一发布结果；私有输出 hash 可用于配对追溯，原始输出不上传。
