对话记录数不是可识别患者数；同人多病例、同义或跨库近重复未知。两个集合完整对话精确匹配为 0，不证明独立。已逐条记录排除原因与原始定位在本地 private `audit.jsonl`；原始文本与转换输出仅存 private。ReMeDi 的 `dialogue` 是原始对话 ID；MedDG 此文件没有对话 ID，采用文件 hash 加零基索引可重定位，生成的 case_id 不是官方患者 ID。两源均无可用患者 ID，不能保证患者级分组。

ReMeDi 原始 base 1,535 可用对话官方 split 标为 `unmapped`；官方另有经过处理的人工标注 train/dev/test 文件，但尚未取得可验证逐病例映射。MedDG 当前文件为官方 train，14,864 条；dev/test 未在本地审查。不能声称 train/dev/test 病例级或患者级无交叉。没有自行分配或伪造官方 split。历史 pilot 精确消息检查见上一轮报告；并未完成所有历史实验、语义或患者级污染检查。

每个状态保留原始顺序、连续同角色轮次和来源定位。`dialogue_history` 在当前医生发言前截断；`reference_answer` 是原医生发言，仅限离线审计；`patient_feedback` 仅取紧接该医生原始发言的患者发言。`router_view` 仅输出历史及元数据，不包含参考、反馈、Gold 或未来医生发言。注意反馈是对原医生话语的观察，并非对任意新 ASK 的反事实回答；因此 ASK 可用率是观察重放上限，不是任意 ASK 的可用率。实际交互须验证提问一致性，不能用后续医生答案替代。

CPU 测试遍历两份源文件的全部有效记录和状态，验证角色、顺序、前缀、即时反馈与来源字段；Oracle 边界采用合成字符串作为单元测试，非合成 Gold 或真实实验。独立 train/dev/test 及患者交叉检查为不可判定，不是通过。完整日志见 `CPU_TEST_LOG.txt`。生成 private 文件：`python3 export_private.py --dataset remedi|meddg --input <本地原文件> --output-dir private/<新目录>`；输出目录必须不存在。重跑测试：`python3 test_cpu.py --remedi <本地原文件> --meddg <本地原文件>`。仅使用可信、校验 SHA 匹配的 pickle；加载器禁止全局对象。

下一阶段需要可追溯的可信目标和独立 Base 正确性判定协议、患者/病例独立性、用途和权利确认、ASK 提问及反馈匹配的冻结协议，才能做有效正式评测。当前不具备正式 Oracle 配对或决定启动 Base 批量推理的条件。
