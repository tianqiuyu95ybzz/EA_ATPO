# 独立病例候选与门槛

在 MedMCQA 作者压缩包的 `dev.json` 中，对实际 4,183 条公开四选项记录按规范化题目及无序选项去除库内重复，并与既有 pilot 100 个病例的公开初始消息按精确题目前缀及无序四选项做排除；2 条历史精确候选和 105 条库内重复被排除，0 条因结构异常排除。再按固定命名空间和官方 UUID 的 SHA-256 排序，取 100 个不同官方 UUID，不按 Gold、模型输出或性能筛选。抽选后核验 100/100 有 1–4 的官方答案键；不输出答案。列表与内容哈希见 `data/independent_candidate_ids.csv`、`data/independent_candidate_manifest.json`。

状态为 **CANDIDATE_NOT_CERTIFIED**，尚不是本项目独立测试集：

- 仅检查了可追踪的 pilot 100 例，尚未覆盖所有其他 worktree 的历史输入、全局近重复、衍生样本或模型预训练；不同文本也可能描述同一病例。原 400 例 Frozen Holdout 没有打开，也没有与其逐条比较。
- 数据来自官方文件名 `dev.json`，不表示它已参与本项目 Router 的 Dev；但其同名 split 与作者 README 数量冲突，须保留档案文件名/摘要并澄清。官方基准答案为考试答案，不是本项目临床医生重新认证的 Gold。
- 这 100 个病例没有已验证的冻结 Router 输入/预测，也没有 ASK 反事实及对应 Base/Expert 配对生成。案例数量不等于评测样本数量；当前独立 Router 评测有效 n=0，不能算指标或 bootstrap。
- 本轮 `nvidia-smi` 显示 GPU 0–7 均有计算进程；GPU 1/7 在项目策略中禁用，其余卡也未满足 V2 无其他计算进程和启动显存/利用率门槛。未启动服务、未向其他人的服务发送请求、未停止进程。

下一步需先完成跨历史实验的病例/题目溯源和近重复审计、明确训练/评测协议及其冻结，确保没有将 Gold 带入 Router 输入；在安全 GPU 窗口用原有冻结模型和一致生成配置取得独立病例的真实三动作结果后，按 case_id 一次性评测。若无法满足这些条件，继续标为 BLOCKED，不得用旧 Dev 或额外重复抽样充数。
