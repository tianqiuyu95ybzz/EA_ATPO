# Expert paired evaluation status

**No V3 evaluation has run:** Base predictions are verified, but reviewed Gold, trained Expert checkpoints and adjudicated Expert outputs are not available. Therefore there are no V3 four-cell counts, correction/degradation rates, confidence intervals, risk–coverage curves or rankings.

The offline metric implementation is prepared for adjudicated records. It reports the four cells, paired accuracy difference, case-cluster bootstrap intervals, correction/degradation/preservation, net gain, action precision/recall/F1, final accuracy, case-grouped results, high-risk final errors and a threshold risk–coverage CSV/SVG. For A, KEEP and ABSTAIN preserve the raw Base string exactly; malformed structured outputs fall back to Base and are counted. For B/C, direct Expert correctness and a separately scored selection policy are reported separately. Ambiguous Gold is excluded from correctness estimates; rejected rows are excluded.

The command-line gate checks the frozen checkpoint/config and Dev-only threshold-calibration manifests, reviewed queue and Base provenance, case/split coverage, scoring-feature allowlist, prediction hashes, timestamps, and either human correctness adjudication or strict approved-option matching. Internal Test has a per-Expert one-attempt marker. These are structural checks, not proof of clinical correctness. Prediction generation, post-generation adjudication, Dev-only threshold calibration and checkpoint freezing have been implemented as separate scripts, but have not been exercised end to end on reviewed data or trained checkpoints.

Synthetic unit tests cover exact Base preservation, all four paired cells, distinct Oracle definitions, independent-versus-selected accuracy, invalid output handling and rejection of pending/unsupported adjudication. These tests validate metric logic only; they do not constitute model evaluation.
