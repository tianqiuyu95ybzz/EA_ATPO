## Cohort construction

The candidate source was the repository's official
`merged_train_dataset.jsonl`: 14,256 unique source records and 14,239 unique
public prompts. It is a single-turn source dataset, not a collection of
multi-turn trajectories. Exact duplicate public prompts were reduced to one
candidate before deterministic hash ranking. Candidate records overlapping
historical case IDs, case-ID hashes, or public-prompt fingerprints were
excluded. The first 200 remaining cases under the frozen SHA-256 ordering were
reserved as an independent, case-ID-disjoint final evaluation cohort.

This is independent of the audited repository-level historical train/dev/test
and experiment cohorts, but it remains drawn from the same official source
dataset. The repository audit cannot establish whether a source case appeared
in a model's pretraining corpus or in untracked external experiments; that
limitation must accompany future performance claims.

deduplicating repeated references to the same path. It records per-source
candidate and selected-test overlap counts and source-file SHA-256 values in
`manifests/final_test_20261120_v1/overlap_audit_detailed.json`. No selected test

The existing frozen case list was regenerated into a temporary verification
directory using the same deterministic selection code. All 200 IDs and the
list hash matched exactly; the frozen manifest was not overwritten. The
generator excludes the `confirmation_20261120` path component from historical
scanning. Window A confirmation outcomes were not opened. The 400-case Frozen
Holdout was not opened. No Window C code or data was modified.

## Leakage boundaries

- Selection uses record IDs and hashes of public user/assistant prompt fields.
- Gold labels and hidden atomic facts are not used to select the cohort and are
  absent from the frozen manifest.
- Future model rollout must receive only the case's currently public state.
- Gold-derived correctness may be joined only after prediction generation for
  metrics and the explicitly labeled retrospective Oracle upper bound.
- Oracle actions are never written as policy predictions and cannot enter
  training or action selection.
- The case IDs are reserved from future training and validation use.

## Future final evaluation

The cohort is not evaluated yet. A valid final run needs one complete ASK,
ANSWER, and DEFER counterfactual outcome per case plus prediction-only outputs
for Q-guided Distillation, Relative Advantage, and the Learned Router. Baseline
actions are generated by the evaluator. Costs are fixed at ASK `0.01`, ANSWER
`0.00`, and DEFER `0.05`; utility is recomputed from correctness and raw call
counts. Inference outputs and outcomes remain private; only aggregate metrics
should be published.

The evaluator reports accuracy, utility, call rates, mean cost, expert
correction and correct-answer degradation rates, case-level paired bootstrap
95% intervals, paired deltas against Always Answer, and risk-coverage curves.
Oracle is an offline, post-hoc upper bound only. No real performance value is
reported in this design/audit document.

## Synthetic verification

Nine unit tests passed using synthetic records only. They cover deterministic
label-blind cohort selection, schema validation, missing-action rejection,
cost recomputation, policy metrics, Oracle separation, paired bootstrap,
risk-coverage generation, and end-to-end output creation without overwriting.
The full log is `SYNTHETIC_TEST_LOG.txt`; it is not a medical experiment result.
